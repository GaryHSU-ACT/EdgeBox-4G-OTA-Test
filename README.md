# EdgeBox-4G-OTA-Test
ACT NKUT EdgeBox-ESP-100 4G OTA 遠端韌體更新測試與版本管理

本儲存庫提供 EdgeBox application 韌體及 OTA 更新資訊，原始碼與歷史備份保留於本機。

目前 OTA 最新版：**2.1.18**。保留設定頁手動「檢查更新 → 開始更新」，不在開機／背景自動更新，不自動切換 Wi-Fi／4G。已經是 2.1.18 的設備不必重複安裝。

## 版本更新紀錄

### 2.1.18 — 2026-10-25

- 感測器清單改為「選類型與 ID 範圍搜尋 → 勾選加入」，另可手動加入；加入即啟用。
- 所有清單項目都能直接停用／啟用及移除，包含原主要氣象／雨雪／土壤項目；不修改感測器本身 ID，不刪歷史。
- 搜尋為唯一 RS485 任務執行的唯讀操作，有進度與停止功能，結束後恢復一般輪詢；搜尋結果是待核對類型的候選。
- 支援最多 32 顆同款土壤，加氣象／雨雪共 34 項；即時讀值只顯示已保存且啟用項目，土壤依 ID 排序，離線仍有狀態與最後成功時間。
- 保留網路、既有感測器清單、風向校正及手動簽章 OTA；資料上傳預設停用，升級保留既有上傳設定，不會自行啟用。
- 新歷史資料使用 agri.telemetry.v3，一組包含整份清單，依序補傳，保留 v1／v2 舊紀錄；正確簽章 ACK 才移除。

驗證：使用已通過 22 個本機與 9 個瀏覽器套件、COM15 實機安裝／重啟驗證的同一份 application bin，未重新編譯。實機完成搜尋勾選加入、手動加入、停用／移除與三感測器跨輪讀值。另完成 34 項大封包 Wi-Fi／4G 替身傳送、錯 ACK 重送與混合版本補傳測試；不代表正式伺服器或滿配實體 34 顆驗收。bin 1,243,648 bytes，SHA-256 `549049faa590023dcaf93f9d328b22eddc64bdc56d94aa82fbfa4c6b55d3e541`。

限制：同出廠 ID 的新感測器仍須逐顆隔離改址；現有主要三角色改址工具不是「新土壤改址並加入」流程，不可用它取代新增感測器的獨立改址工具。32 顆為軟體容量，RS485 電氣負載、供電、線長需現場驗證。清單 v2／歷史 v3 保存後，降版需配套還原設定與補傳規劃，不能只刷舊 app 或清空資料。

### 2.1.0 — 2026-10-10

新增設備內建網路設定頁，支援選擇 4G 或 Wi-Fi 作為對外連線。

- 預設使用 4G，同時開啟 `EdgeBox-xxxxxx` 設定熱點；4G 模式不連接外部 Wi-Fi。
- 可搜尋附近 Wi-Fi、選擇名稱及輸入密碼，也可手動輸入隱藏 SSID。
- 將網路選擇、SSID 與密碼保存至 ESP NVS，下次開機沿用設定。
- Wi-Fi 模式關閉 4G 板上供電；Wi-Fi 取得 IP 後關閉設定熱點。
- Wi-Fi 每次嘗試最多 15 秒，連續三次失敗保留熱點供重新設定；已連線後斷線會重新開啟熱點並重試。
- 設定頁顯示目前網路、連線狀態、電信／Wi-Fi 名稱、訊號強度及四格訊號圖示。
- 4G 訊號以 CSQ 換算 RSSI 估計值，未知訊號不顯示為滿格；Wi-Fi 使用 RSSI。
- 新增 Wi-Fi HTTPS OTA 傳輸及 HTTP Range 續傳，沿用版本、板型、大小與 SHA-256 驗證。
- 網頁服務與 RS485 使用獨立任務，4G 等待及 OTA 期間可查看設定頁；保存設定後等待目前操作完成再重啟。
- 新增序列命令 `a` 手動開啟設定熱點，保留 `c` 檢查更新、`s` 查看狀態。

設定入口：連上設備熱點後，開啟 `http://192.168.4.1`。預設熱點密碼 `EdgeBox2026`；頁面帳號 `admin`、密碼 `EdgeBox2026`。Wi-Fi 成功後，可由同一個 Wi-Fi 網路以設備 IP 開啟設定頁。

驗證：Arduino 編譯通過，application 使用 OTA 分區約 82%；瀏覽器模擬測試通過訊號顯示、Wi-Fi 搜尋選擇及保存流程。實機網路切換、RF、供電及斷線重連仍待現場測試。

### 2.0.0 — 2026-10-10

首支 RS485 與 4G GitHub OTA 整合版。

- UART1 以 9600 baud 讀取氣象站 ID 1、雨雪 ID 2、土壤 ID 11，每 30 秒輪詢。
- 回應檢查地址、長度及 Modbus CRC，讀取失敗重試；完整 CSV 僅在當輪三顆感測器皆有效時輸出。

- 新增 `agri-manifest.txt`，核對板型、檔案大小、SHA-256 與固定 Git commit 的韌體網址。
- 韌體逐塊寫入另一個 OTA 分區，完整驗證後才切換開機目標並重啟。
- 保留 chunk 1024 bytes、間隔 75 ms，加入 chunk 重試及整次下載的 session 恢復次數限制。
- 修正 AT 回應跨等待窗口時半行文字遺失，以及逾時計算減法下溢。

## OTA 檔案與操作

- `firmware.bin`：編譯後的 application，非 bootloader、分區表或 merged image。
- `version.txt`：版本號，保留供舊測試流程使用。
- `agri-manifest.txt`：目前整合版使用的更新清單，含版本、板型、大小、SHA-256 及固定 commit 下載網址。
- `agri-manifest.txt.sig`：清單的 ECDSA-P256 簽章，與設備既有信任公鑰核對；缺少／不一致會拒絕更新。

首次安裝須接線燒入具 OTA 功能的整合版與正確分區配置。2.1.5 以上從設定頁先按「檢查更新」，再另按「開始更新」；序列 `c` 也只檢查。新版保留 OTA 與相同分區設定。上方較舊版本的自動 OTA 敘述只代表當時行為。

## 目前限制

這是開發驗證版。OTA 已有 ECDSA-P256 來源簽章及 SHA-256 完整性驗證，尚未配置 OTA TLS CA 驗證或新版本開機失敗自動回退。選用資料上傳另使用設定的 HTTPS CA 與設備 HMAC，與 OTA 通道分開。Wi-Fi 設定尚未啟用 Flash 加密；Wi-Fi 未支援 Enterprise 帳號認證或需網頁登入的網路。網站／資料庫尚未正式接入，上傳預設停用。
